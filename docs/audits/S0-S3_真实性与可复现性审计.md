# NomadHub General3 V1.7 — S0～S3 真实性与可复现性审计

## 审计结论

前面阶段并非全部是假文件：本地 ZIP、JSON、PNG、GLB 和脚本真实存在，SHA-256 清单匹配，S2/S3 GLB 也能正常解析。

但阶段名称、通过结论和验证强度存在明显夸大，当前 `S3 PASSED / S4 IN_PROGRESS` 状态无效，必须暂停 S4。

```text
S0 = CONCEPT_ACCEPTED
S1 = REWORK_REQUIRED
S2 = PROTOTYPE_ONLY / REWORK_REQUIRED
S3 = REWORK_REQUIRED
S4 = PAUSED_BY_AUDIT
```

## S0

外观参考图可以作为概念方向，但不是 CAD、测绘图或厂商工程图。图板日期与项目时间不一致，且图板保留 4.500 m 轴距，而后续规范改为 5.150 m，因此不能继续称为统一权威工程参考图。

## S1

S1 文件真实，但毫米级坐标属于人工设定，不是测量结果。后轴由 1.265 m 移至 1.905 m 后，没有重新计算全部窗口、门舱和轮拱冲突。

按修订值重新计算：

- 左后储物舱与轮拱重叠约 115 mm；
- 右后储物舱与轮拱重叠约 105 mm；
- 右中储物舱距轮拱约 50 mm，低于原规范要求的 80 mm。

因此 S1 原 PASS 已失效。

## S2

S2 R19 GLB 真实有效，节点、三角面、法线和包围盒多数统计与文件一致。但完整项目中没有任何 `.blend` 文件，实际生成方式是 Python + trimesh + Shapely，自定义十二视图来自 CPU rasterizer。

因此它是程序化 GLB 原型，不是 Blender 连续低面控制笼。`visual_blockout_consistent=true` 等视觉门禁属于人工写入，不是独立验证结果。

## S3

S3 R3 GLB 真实存在，结构节点和几何统计基本真实。但它仍由 trimesh primitive 和网格合并生成，视觉上未达到产品级精模。

此外：

- 静态和开启 GLB 都没有 AnimationClip；
- 开启验证只是另存节点已旋转的 GLB；
- 间隙检查使用 nearest BODY_SHELL vertex approximation，不是真实三角面碰撞；
- 实际模型仍有检修舱与后轮区域侧投影冲突；
- 只有 15/78 图元带 TEXCOORD_0；
- 没有 Blender 原生工程。

因此 S3 不能保持 PASSED。

## GitHub

GitHub 中存在阶段 JSON/Markdown，但找不到状态文件所列出的 S2/S3 GLB 交付物。直接读取模型文件返回 404，代码搜索也无结果。

当前仓库只能证明阶段元数据被提交，不能证明完整模型资产已托管或可复现。
